SECTION 02

What We're Building

A physical sidecar gateway enforcing deterministic state invariants before tool execution.

Current autonomous agent security relies on intent detection: asking another LLM (e.g. LlamaGuard or NeMo Guardrails) whether a user message seems malicious. In an autonomous business agent with tool execution credentials, this approach fails because natural language prompts are fundamentally Turing-complete.

LEASH replaces probabilistic prompt filtering with a deterministic action gateway. Siting as an inline sidecar between the LLM and backend execution tools (database clients, payment APIs, refund gateways), LEASH does not attempt to guess what the model "thought." Instead, it intercepts the concrete structured action contract and validates it against mathematical ground truth.

The Core Invariant Contract:
  • ✓ Recipient Identity: recipient_email == order.payer_email in SQLite records.
  • ✓ Balance Preservation: refund_amount ≤ order.remaining_balance.
  • ✓ Quorum Enforcement: Mutations exceeding $300 require human supervisor quorum sign-off.
  • ✓ Cryptographic Minting: Backend tools drop all calls lacking a valid HMAC-SHA256 receipt.

SECTION 03

The Threat Model: Invariants vs Intent

Why prompt classification guarantees failure and deterministic invariants guarantee safety.

In a tool-augmented agent architecture, an attacker has dozens of evasion vectors: Unicode homoglyphs, low-resource languages (e.g. Kannada, Hindi, Swahili), multi-step prompt laundering, and indirect payload injection inside customer tickets or database rows. An NLP guardrail must predict the infinite permutations of human expression. A state invariant only checks one equation.

Benchmarking 48 real-world autonomous agent attacks across 4 laundering classes and 42 benign control traces.

To evaluate LEASH under production conditions, we created LaunderBench-mini: a testbed of 90 total scenarios split into 48 adversarial attack traces and 42 benign customer interactions.

1. Foreign Language Prompt Laundering (n=12) Indirect prompt injection written in Kannada, Hindi, and transliterated Kannada directing the agent to divert funds.

4. Markdown Exfiltration & PII Leaks (n=12) Agent exfiltrating database records via markdown image links to external domains.

Across all 48 adversarial cases, LEASH achieved a 100% defense rate (0 escapes) while maintaining a 0.0% false block rate on all 42 benign control operations.

def verify_gateway_receipt(action_payload: dict, receipt_token: str) -> bool:
    expected_token = hmac.new(
        GATEWAY_SECRET, canonical_json(action_payload).encode(), hashlib.sha256
    ).hexdigest()
    if not hmac.compare_digest(expected_token, receipt_token):
        raise SecurityException("UNAUTHORIZED_ACTION: Missing or invalid LEASH receipt")
    return True
SECTION 06

Known Limitations, Stated Honestly

Engineering boundaries: where LEASH works and what it does not attempt to solve.

In the interest of rigorous engineering, we explicitly document the operational boundaries of this design:

1. Pre-Tool Token Denial of Service

LEASH intercepts actions at the tool boundary. If an adversarial prompt forces the LLM to enter an infinite thinking loop or generate 50,000 conversational tokens without calling a tool, LEASH cannot stop token burn.

2. Quorum Fatigue & Escalation Flood

If an attacker continuously generates borderline transactions requiring supervisor quorum, human operators may suffer approval fatigue. Circuit breakers help mitigate this, but human oversight remains a bottleneck.

3. Invariant Schema Maintenance

System-of-Record invariants require schema synchronization with core business databases. If an order schema changes without updating the policy engine, false blocks may occur.
